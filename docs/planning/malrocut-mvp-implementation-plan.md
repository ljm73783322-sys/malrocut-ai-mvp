# Malrocut AI MVP 구현 계획서

## 1. MVP 최종 범위
- **대상 사용자**: 70대 시니어 사용자도 클릭 2~3번만으로 캡컷(CapCut) 수준의 편집 결과를 얻을 수 있는 초단순 UI/UX.
- **입력 스펙 제한**: 1080p 이하, 최대 3분, 100MB 이하의 MP4 영상 (서버 오버헤드 및 실패 확률 최소화).
- **기본 편집 변화 세트 (원터치 자동 적용)**:
  1. 기존 영상의 하단 자막 영역을 부드러운 블러(Blur) 밴드로 가림 처리.
  2. 음성 인식(STT) 후 시니어 친화적인 고대비 큰 폰트(검은색 굵은 테두리 + 노란색/흰색 글씨)로 새 자막 삽입 및 다국어 단순 번역 (싱크 유지 보장).
  3. 무음 구간 자동 탐지 및 단순 컷 편집.
  4. 인물 얼굴 기준 화면 1.2배 확대(Zoom-in) 및 중앙 정렬 (화면 몰입감 증대).
  5. 화면 색감 보정 (화사하고 선명한 '밝음' 필터 프리셋 1종 일괄 적용).
  6. 결과물 영상 첫 컷을 활용한 대형 텍스트 합성 썸네일 자동 생성.
- **출력 결과**: `edited_video.mp4`, `subtitle.srt`, `thumbnail.jpg` 파일 생성 및 다운로드.

## 2. 제외할 기능 (Analyst Review 반영)
- **프롬프트 기반 장면 순서 재배치**: 비전 모델 연산 과부하 및 실패 리스크(의미 훼손) 방지를 위해 제외.
- **자막 문장의 맥락 기반 재구성**: 오디오-자막 싱크 어긋남의 치명적 결함을 방지하기 위해, 원본 타임스탬프를 유지하는 '단순 번역'으로 대체.
- **기타 Out of Scope**: 음성 클론, 립싱크 맞춤 보정, 고급 트랜지션, 캡컷 데스크톱 연동, 플랫폼 자동 업로드, 모바일 네이티브 앱, 완벽 AI 인페인팅, 다수 숏폼 자동 분할 추출.

## 3. 전체 개발 단계
1. **기획 및 설계**: 최종 요구사항 문서화 및 파이프라인 아키텍처 설계 (완료).
2. **인프라 및 코어 모듈 세팅**: FastAPI, FFmpeg, Whisper/OpenCV 모델 환경 구성.
3. **비디오 프로세싱 코어 개발**: 비디오/오디오 분리 -> 컷 편집 -> 자막 처리 -> 보정 -> 썸네일 생성 파이프라인 구축.
4. **백엔드 API 개발**: 파일 업로드, Job 관리, 상태 반환, 파일 다운로드 API 구현.
5. **프론트엔드 UI 개발**: Next.js 기반 직관적인 UI(대형 버튼, 한국어 안내) 및 Progress Bar 연동.
6. **통합 테스트**: 프론트-백 연동 테스트 및 엣지 케이스(무음 영상, 큰 해상도 등) 예외 처리.
7. **MVP 배포**: 클라우드(또는 로컬 서버) 배포 및 파일 24시간 보존/삭제 정책 적용.

## 4. 프론트엔드 구현 범위
- **UI/UX 원칙**: 복잡한 설정창 제거, 큼직하고 명확한 버튼 디자인, 전문 용어 배제(예: "렌더링" -> "영상 만드는 중").
- **주요 페이지**:
  - **메인/업로드 화면**: 화면 전체의 1/3을 차지하는 거대한 파일 업로드 영역.
  - **대기/진행 화면**: 비디오 처리 과정(1단계: 분석 중, 2단계: 편집 중, 3단계: 마무리 중)을 크고 직관적인 Progress Bar로 표시.
  - **결과/다운로드 화면**: 편집 완성본 재생 플레이어와 눈에 띄는 "완성본 저장하기", "자막 다운로드", "썸네일 다운로드" 버튼.

## 5. 백엔드 구현 범위
- **프레임워크**: FastAPI (Python)
- **핵심 역할**:
  - 비동기 처리: 클라이언트가 오랫동안 기다리지 않도록 비디오 처리를 백그라운드 Job Queue로 분리.
  - FFmpeg 파이프라인 래퍼(Wrapper) 구축: 여러 영상 처리 과정을 하나의 파이썬 클래스/함수 스트림으로 묶음.
  - 스토리지 관리: 임시 디렉토리(`/tmp` 또는 특정 버킷)에 원본/결과물 저장 후 24시간 스케줄러를 통한 삭제.

## 6. API 구현 순서
1. `POST /api/v1/video/upload` : MP4 업로드 및 Job ID 발급
2. `GET /api/v1/video/status/{job_id}` : 클라이언트 폴링용 현재 진행 상태 퍼센트 및 상태 메시지 반환
3. `POST /api/v1/video/process` : 백그라운드 태스크 시작 (보통 Upload 후 자동 트리거)
4. `GET /api/v1/video/download/{job_id}/{type}` : 파일 타입(`video`, `srt`, `thumbnail`)에 따른 파일 스트리밍 반환

## 7. 영상 처리 파이프라인 구현 순서
1. **검증**: 파일 스펙 검증 후 오디오(mp3/wav)와 비디오 분리.
2. **분석**: 오디오 트랙에서 무음 구간 타임스탬프 추출 및 얼굴 인식(OpenCV)을 통한 인물 위치 좌표값 도출.
3. **컷팅**: 타임스탬프 기반 FFmpeg 컷 편집 (자르기 및 이어붙이기). 오디오가 튀지 않도록 컷 사이에 짧은(0.1초) 크로스페이드 강제 적용.
4. **리프레이밍**: 얼굴 좌표를 기준으로 크롭(Crop) 및 1.2배 Zoom-in 진행.
5. **보정**: 전체 프레임에 밝고 화사한 LUT 필터 적용.

## 8. 자막 제거/삽입 구현 순서
1. 영상 하단부(약 15%~20% 영역)에 정적 블러(Blur) 박스를 FFmpeg로 씌워 기존 자막을 덮음.
2. 컷 편집 전의 원본 오디오에서 Whisper 모델을 이용해 텍스트와 타임스탬프 추출(STT).
3. 컷 편집 맵에 맞게 자막 타임스탬프 재조정.
4. 시니어 시력에 맞춘 초대형/고대비 텍스트 옵션을 주어 FFmpeg 오버레이 실행. (별도의 `.srt` 파일 생성 포함)

## 9. 썸네일 기능 구현 순서
1. 모든 편집이 끝난 결과물에서 프레임 하나(가급적 얼굴이 선명한 프레임 또는 0초 지점 프레임) 추출.
2. 밝기를 20% 낮추는 어두운 틴트 레이어 합성 (텍스트 가독성 향상 목적).
3. 정중앙에 "자동 편집 완성!" 과 같은 직관적인 한글 타이틀 텍스트 합성.
4. `.jpg` 포맷 저장 및 다운로드 링크 활성화.

## 10. 테스트 기준
- **수용 기준 (Acceptance Criteria)**:
  - 70대 사용자를 가정한 블라인드 테스트 시, 타인의 도움 없이 3번 이내의 클릭으로 편집 결과물 다운로드에 성공해야 함.
  - 생성된 비디오에 기존 자막이 깔끔하게 가려지고, 새 자막 오타율이 수용 가능한 범위 내인가?
  - 파일 용량 100MB 초과 영상 업로드 시, "파일이 너무 큽니다. 더 짧은 영상을 올려주세요." 와 같은 친절한 한글 오류창이 즉각 표시되는가?
- **성능 (NFR)**: 전체 프로세싱 시간이 원본 영상 길이의 최대 1.5배~2배 이내로 끝날 것.

## 11. 위험 요소와 대응 방법
1. **서버 다운/과부하**: 
   - 대응: 백엔드 동시 처리(Concurrency) 제한을 엄격하게 걸어 서버 마비를 방지.
2. **BGM(배경음악)이 커서 음성 인식 실패**: 
   - 대응: Whisper 인식 실패 또는 무음 처리 스킵 오류 시 파이프라인을 멈추지 않고, "음성을 완벽히 인식하지 못했습니다." 자막만 띄운 채 그대로 원본 컷팅 없이 진행 (에러로 인한 멈춤 방지).
3. **영상 내 인물이 없는 경우**: 
   - 대응: 얼굴 인식이 실패하면 Zoom-in 및 중앙 정렬 과정을 안전하게 패스(Bypass)하도록 분기 처리.
