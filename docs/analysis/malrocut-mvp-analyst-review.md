# Malrocut AI MVP - Analyst Review

**문서:** `docs/requirements/malrocut-mvp.md`
**작성자:** Analyst 에이전트
**목적:** 기획서의 논리적 허점, 기술적 한계 및 요구사항의 완전성을 검토하여 구현 전 리스크를 최소화합니다.

---

## 1. 누락된 요구사항 (Missing Requirements)
- **파일 스펙 제한**: 업로드 가능한 최대 영상 길이(예: 3분, 10분 등), 최대 파일 용량(예: 500MB), 지원 해상도(예: 1080p) 및 오디오 코덱 기준이 명시되어 있지 않습니다.
- **성능 및 응답성 (NFR)**: 영상 처리에 소요되는 허용 시간(예: "영상 길이의 1.5배 시간 이내 처리 완료")에 대한 기준이 없습니다.
- **데이터 보존 정책**: 사용자가 업로드한 원본 영상과 처리된 결과물을 서버에 얼마 동안 보관할지(예: 24시간 후 자동 삭제)에 대한 보안 및 스토리지 정책이 누락되었습니다.
- **사용자 피드백 UI**: 긴 비디오 처리 시간 동안 사용자에게 보여줄 진행률(Progress Bar) 표시 및 상태(업로드 중, AI 분석 중, 렌더링 중) 안내 요구사항이 필요합니다.

## 2. 불명확한 기능 범위 (Unclear Feature Scope)
- **프롬프트 기반 장면 재배치**: 자연어를 통해 "특정 컷의 순서 변경"을 지시하는 방식이 불명확합니다. 사용자가 타임스탬프를 지정하는지, 아니면 화면 내용(예: "바다 장면을 맨 앞으로 보내줘")을 기준으로 AI가 씬을 탐지해야 하는지 명확한 정의가 필요합니다.
- **무음 구간 제거 기준**: 어느 정도의 데시벨(dB) 이하를 무음으로 볼 것인지, 최소 몇 초(ms) 이상 지속되어야 무음으로 간주할 것인지 기준치가 없습니다.
- **썸네일 텍스트 합성**: 썸네일에 들어갈 텍스트 레이어를 사용자가 직접 입력하는지, 아니면 영상 내용을 바탕으로 LLM이 자동 생성하는지, 텍스트의 폰트나 위치는 고정인지 커스텀인지 불명확합니다.
- **얼굴 중앙 정렬 (Auto-framing)**: 영상에 두 명 이상의 인물이 동시에 등장하거나, 인물이 전혀 등장하지 않는 풍경 영상일 경우의 처리 기준이 모호합니다.

## 3. MVP에서 위험한 범위 확장 요소 (Scope Creep Risks)
- **문장 맥락에 맞는 재구성 (다국어 지원)**: 자막을 번역할 때 맥락에 맞춰 '재구성'하게 되면, 원본 오디오의 발화 타이밍(Timestamp)과 자막의 싱크가 어긋나는 치명적인 문제가 발생합니다. MVP에서는 **원문의 타임스탬프를 엄격히 유지하는 단순 번역**으로 축소하는 것이 안전합니다.
- **프롬프트 기반 장면 컷 편집 및 재배치**: 영상의 의미(Semantic)를 이해하여 컷을 재배치하려면 멀티모달 비전 모델의 개입이 필요할 수 있으며, 연산 비용과 실패 확률이 높습니다. MVP에서는 '텍스트 대본(Transcript) 기반의 단순 컷 삭제'까지만 포함하는 것을 권장합니다.

## 4. 수용 기준이 부족한 항목 (Lacking Acceptance Criteria)
- **기존 자막 제거**: 어느 정도 가려지면 성공으로 볼 것인가? (예: 기존 자막 영역에 단순히 100% 블러 밴드를 씌우는 것인지, 동적으로 자막 박스 크기만큼만 가리는 것인지)
- **색감 보정**: 프롬프트("영화처럼 만들어줘")에 대해 AI가 얼마나 정확한 LUT(Look-Up Table)를 매칭해야 합격인지 주관적입니다. 사전에 정의된 N개의 필터 프리셋(예: Cinematic, Vintage, Bright 등) 중 하나를 매핑하는 방식인지 기준이 필요합니다.
- **새 자막 생성**: 생성된 자막의 디자인(크기, 폰트, 색상, 테두리 등)에 대한 기본값이 기획되어 있지 않습니다.

## 5. 구현 전에 반드시 답해야 할 질문
1. **인프라/비용**: 무거운 비디오 인코딩(FFmpeg)과 AI 모델(Whisper, Face Detection 등)을 동시에 돌릴 서버 인프라(GPU 여부)와 예상 비용 구조는 어떻게 되는가?
2. **오디오 튀는 현상**: 컷 편집(특히 무음 제거) 시 잘려나간 오디오 트랙이 튈(Pop) 텐데, 짧은 오디오 크로스페이드(Crossfade)를 시스템적으로 강제 적용할 것인가?
3. **BGM 처리**: 원본 영상에 배경음악(BGM)이 크게 깔려 있어 Whisper가 음성을 추출하지 못하거나 무음 탐지에 실패할 경우, 어떻게 처리할 것인가? (Vocal Remover(음원 분리) 모델을 파이프라인에 추가할 것인가?)

## 6. Edge Cases (예외 상황)
- 프롬프트에 서비스가 지원하지 않는 불가능한 명령(예: "배경을 비 오는 날씨로 합성해줘", "목소리를 여성으로 바꿔줘")이 포함되었을 때의 에러 핸들링 메세지.
- 영상에 이미 화면의 1/3을 덮는 매우 큰 하드코딩 자막이 있어, 제거/블러 처리 시 영상의 주요 시각 정보가 훼손되는 경우.
- 동영상이 1프레임이거나 오디오 트랙 자체가 아예 없는(Mute) 영상을 업로드한 경우.

## 7. Planner에게 넘길 권장사항 (Recommendations)
1. **기능 축소 제안**: MVP 버전의 빠른 출시와 안정성을 위해 **'장면 순서 재배치'와 '자막 문장 재구성' 기능은 제외**하거나 Post-MVP 로드맵으로 미루는 것을 강력히 권장합니다.
2. **제약 사항 명문화**: 사용자가 업로드할 수 있는 비디오 스펙(1080p 이하, 최대 3분 제한, 100MB 이하)을 기획서 1순위로 추가하여 초기 서버 오버헤드를 막아야 합니다.
3. **UX 개선안 보강**: 사용자가 텍스트 대본을 직접 수정할 수 있다고 명시되어 있는데(2.2절), 이 수정 작업이 백엔드의 비디오 렌더링 파이프라인 중 어느 시점에 개입해야 하는지(비동기적 사용자 개입) 프로세스 흐름도(Flowchart)의 추가가 필요합니다.
